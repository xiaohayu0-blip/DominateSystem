# 管理学院制度问答网站实施计划

**Goal:** 从零构建浏览器可用、持久化、可审计的网站，演示与真实接入分别验收。

**Architecture:** 单体 API + React 网站 + SQL 数据库 + 同库持久化邮件队列。普通用户会话与管理员认证分离，原文件使用受控存储接口。

**Tech Stack:** Python 3.14.3、FastAPI、SQLAlchemy、Alembic、PostgreSQL 17；React、TypeScript、Vite、Node 24.13.0、npm 11.6.2。开发/测试可使用独立 SQLite；容器使用 PostgreSQL。

## 需求与替换

| 最新规则 | 决策与边界 |
|---|---|
| 从零创建网站 | 不复用旧代码、配置、数据库或依赖；只读三份需求文档 |
| 手机号免验证 | 每次登记建立独立自报资料和随机浏览器会话；不按手机号恢复或暴露档案，替换旧文档同号复用规则 |
| 家长多个孩子 | child_entries 只引用家长登记，不引用学生；无切换身份或绑定入口 |
| 资料与问答长期保存 | 问答保存提交时资料快照；无自动过期删除 |
| 周报后台处理 | 北京时间周一边界，同源问题池；不发送邮件 |
| 一周预警留存 | 用户已确认仅预览清理候选，不提供实际删除命令 |
| 模型与邮件 | DeepSeek/模拟模型、SMTP/模拟发送接口分离；真实外发默认关闭 |
| 检索 | 中文字词关键词与字符哈希向量混合，免下载本地大模型；不宣称BGE语义效果，真实资料需评测 |

## 数据模型与权限

registrations → child_entries；sessions 保存不可逆令牌摘要与到期时间。questions 保存登记快照、答案、引用、子事项与运行信息。issues 对应失败子事项，合并只建立组关系，保留原始记录。documents → chunks 保存版本和定位；发布决定检索可见性。events → mail_jobs → mail_attempts 与人工处置记录分离。admins 使用 scrypt 散列；audit 记录管理员关键操作。

普通用户只能读取当前随机会话下自己的问答及已引用来源；没有手机号查询接口。管理员独立 cookie、服务端鉴权、会话撤销；文件原文仅管理员可下载，普通用户仅可获取自己已引用的已发布摘录。读写接口同源校验，cookie HttpOnly/SameSite；正式部署启用Secure与HTTPS。

## 分阶段执行与验证

1. 工程与迁移：创建配置、锁文件、模型、迁移；新库升级、幂等升级和健康检查。
2. 身份与认证：登记、孩子条目、独立管理员会话；测试同号隔离、越权、快照。
3. 资料与问答：四格式解析、草稿/发布、混合检索、引用校验、DeepSeek适配；测试年份、年级、冲突、多事项及故障。
4. 后台闭环：问题合并、历史、正式答复、复测、北京时间周报；测试状态约束和边界。
5. 预警：先落库后问答、持久化租约队列、模拟/SMTP、重试与预览；测试重启恢复、幂等及不外发。
6. 网站：登记、聊天、出处、后台核心页面与响应式；类型检查、代码检查、构建与浏览器端到端验证。
7. 运维：开发/演示启动、Compose、备份恢复、升级回滚；记录本次真实证据与未验证项。

## 工程选择

不采用微服务/Kubernetes。SQLite仅便于无Docker环境开发；生产使用PostgreSQL。检索采用可重建的确定性哈希向量与关键词，节省模型下载与内存，但同义语义召回较弱；提供Retriever接口方便替换。模型只输出证据选择及摘录，服务端以原文构造答案与引用，优先可核查性；不承诺消除错误。
