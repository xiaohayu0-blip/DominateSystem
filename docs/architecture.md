# 架构、数据模型与权限

## 架构决策

React网站通过同源 `/api` 访问 FastAPI；数据库保存业务数据，受控文件目录保存原文件。生产使用PostgreSQL，开发/测试/Demo允许独立SQLite。API单进程维护并发与速率上限；邮件worker是同一工程内的独立进程，使用同库队列，不引入消息中间件。生产不应擅自增加API副本，否则需先把限流和模型预算移入共享数据库。

与服务拆分相比，这个结构减少部署组件和运维成本。字符哈希向量与关键词组合无需下载BGE或部署本地大模型，但不是预训练语义向量，召回能力有限。接口 `Retriever` 可替换。`AnswerModel`、`FileStore`、`MailSender` 分别隔离DeepSeek/模拟、原文件和SMTP/模拟通道。

DeepSeek适配依据官方 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 和 [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。模型只筛选证据和逐字摘录，服务端验证ID和摘录后展示完整证据片段。模型不生成来源URL。当前采用保守原文回答，未实现自由长篇综合推理。

## 主要对象

| 表 | 关系与留存 |
|---|---|
| registrations | 一次浏览器登记，自报学生/家长资料；手机号不唯一、不作认证；长期保存 |
| child_entries | 仅引用家长registration；不引用任何学生账号；长期保存 |
| sessions | 随机32字节令牌的SHA256摘要、角色主体、到期时间；用户与管理员cookie分离 |
| admins | 独立账号，scrypt加盐散列；不开放公开注册 |
| documents/chunks | 版本、范围、有效期、发布状态、定位、原文、派生向量；向量可重建 |
| questions | 原始问题、完整回答、范围、引用元数据、提交资料快照、请求幂等键、运行状态 |
| issues | 失败子事项、原因、处理状态、负责人、依据、历史与复测；合并不删除原始行 |
| events | 每个危险问题独立事件，检测器版本、人工处置状态与记录 |
| mail_jobs/mail_attempts | 独立通道、状态、租约、尝试与正文副本；不存邮箱授权码 |
| audit | 管理员登录退出、资料维护、处理及敏感资料查看等操作记录 |

所有业务时间按UTC无时区值保存，API时间由客户端明确按UTC解释；周报使用 `Asia/Shanghai` 周一00:00至下周一00:00左闭右开区间。历史引用与人员快照不随资料修改而变化。

## 权限边界

- 用户登记只创建新资料和随机会话，不查询已有手机号。浏览器cookie为HttpOnly、SameSite=Strict；正式环境强制Secure/HTTPS。用户会话24小时，管理员8小时，可配置。
- 普通用户只能访问自己会话登记的问答；没有按手机号查档案、找回历史或访问后台的接口。家长孩子手机号与学生一致也没有额外权限。
- 普通用户仅能读取自己问答已引用的原文片段及元数据；管理员才可下载完整附件。历史来源停用时继续显示当时引用并标注状态。
- 管理员鉴权在每个服务端后台接口执行；退出撤销服务端会话。管理员账号不使用普通用户手机号入口。
- 同源Origin和Sec-Fetch-Site校验防止浏览器跨站写操作；React转义文字，不渲染不可信HTML。SQLAlchemy参数化查询。文件名只用作显示，实际存储随机ID，路径严格限定根目录。
- PDF/DOCX/XLSX/CSV限制大小、展开大小、页数/行数；拒绝宏文档、不支持格式和加密文件。解析失败保留草稿，提供重试；未发布不进入检索。

## 状态与事务

问题提交在同一事务保存登记快照、原问题、危险事件与邮件任务，然后才执行后台问答。HTTP202返回事件提示，无需等待模型。问答重试按登记ID+请求ID唯一约束去重。完成回答时同一事务保存答案和失败子事项。API进程重启时把未完成生成明确转成技术故障；不伪装为缺资料。

问题池处理使用revision条件更新防止静默覆盖。缺资料等业务问题完成需关联已发布依据，且最近复测通过、引用依据与完成依据相交。合并必须同年度/年级/原因，由管理员核对其他条件，保留所有发生记录和人员。周报读取同一问题池，不维护第二套处理状态。

发信任务通过数据库条件UPDATE领取并持有60秒租约。模拟任务可在租约超时后恢复；SMTP任务租约过期转为投递不确定，避免发送后崩溃造成盲目重发。SMTP无法保证严格exactly-once：邮件服务器接受和数据库提交之间没有分布式事务。固定Message-ID辅助核对，不承诺收件端自动去重。已成功任务不允许管理员重复发送；确定失败有限指数退避，人工可重试。

按用户要求，7天留存仅提供预览。事件、问答、人员、处理历史和审计均不自动删除。
