# Demo操作手册

## 打开网站

启动方式见README。用户端 <http://localhost:5173/>，管理员后台 <http://localhost:5173/#/admin>。`localhost`仅能在当前电脑使用，不能直接发给手机。跨设备演示需单独配置可达局域网地址、监听地址与PUBLIC_ORIGIN；当前未公开监听。

管理员 `demo-admin`，随机密码请在本机 `backend/runtime/demo-access.txt` 查看。不要把该文件上传到GitHub或截图公开。

## 一套完整流程

1. 首页顶部确认“合成制度 / 模拟模型 / 模拟邮件，不外发”。
2. 选择「注册账号」，填写虚构姓名、`13800000001`、演示专业和班级，并设置至少 8 位的演示密码。退出后选择「登录账号」，用注册时填的姓名和密码进入同一登记资料。当前姓名登录要求姓名唯一。旧版独立账号名仍可登录其原账号。
3. 提问“2026年度奖学金申请需要哪些材料？”；答案来自合成制度，点来源卡查看发布单位、版本、年度、定位及原文。
4. 问“2025年度奖学金申请需要哪些材料？”；核对往年版本。
5. 选择 2023 年问「数学建模竞赛省级三等奖综测加几分？」。保留「承接上次提问条件」后问「那2024年呢？」，核对年份和引用。
6. 问“实习申请几天提交？”；两份合成文件分别5天/8天，呈现冲突待确认。
7. 问“奖学金申请材料？校外住宿补助如何申请？”；有依据的事项回答，无依据的事项入池。
8. 退出，登记家长 `13900000001`，填写两个孩子。可与前述学生填写相同手机号，不会绑定，也不能取得学生问答。没有选择孩子身份的步骤。
9. 管理员登录，进入问题池，搜索“住宿补助”，展开原始记录和全量自报资料。
10. 进入资料维护，录入正式答复。示例标题“【合成演示】住宿补助申请说明”，单位“虚构学院”、确认人“虚构老师”、日期填当前日、依据“合成演示说明”，正文“校外住宿补助申请需提交申请表与住宿证明，由学院人工审核。”
11. 保存草稿，展开新资料，确认元数据，点“发布此版本”。复制资料编号。
12. 回问题池，展开原问题，点“复测原问题”。重新展开后核对复测通过和来源，填关联资料编号、负责人和备注，状态改“已完成”，保存。
13. 后台周报与问题池使用同一处理状态。邮件发送状态单独显示。邮件工作进程在北京时间每周一 09:00 发送上周新增问题，同一周只入队一次。没有新增问题时不发空邮件。工作进程错过时间后，若在当周恢复运行，会补排该周应发的批次。演示环境使用模拟通道。

## 本机启用 DeepSeek

在 `backend/.env` 把 `MODEL_MODE` 改为 `deepseek`，并填写 `DEEPSEEK_API_KEY`。默认模型为 `deepseek-flash`。保存后重启后端，在「配置状态」确认模式，再用有出处的问题验证真实请求。密钥只放在后端配置中。真实 SMTP 周报需要另行配置发件服务和 `WEEKLY_RECIPIENT`，并获得外发授权。

## 本机启用 BGE

在 `backend` 目录安装可选依赖、升级数据库并生成索引。

```powershell
uv sync --locked --extra bge
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.cli bge-index
```

首次索引会下载 BAAI/bge-small-zh-v1.5 的 ONNX 权重。之后后端用 CPU 和本地缓存推理，资料片段与查询向量都在本机生成。把 `backend/.env` 的 `EMBEDDING_MODE` 设为 `bge`，重启后端，工作台「配置状态」会显示检索模型。启用后新资料自动生成 BGE 向量，年份、年级和资料范围仍由规则筛选。部署到服务器时，在服务器安装相同依赖并生成索引，或挂载已下载的模型缓存。恢复原有检索可将模式改为 `hash` 后重启。

## 预警只做虚构演示

在用户页面输入“演示用例：孩子说他不想活了”。网站及时显示求助提示，数据库先建立事件和邮件任务；worker默认约每秒检查任务，模拟状态变为“模拟已发送”。不会向任何邮箱发送。

管理员进紧急事件，核对两类状态：“模拟已发送”和“待处理”。填写人工处置备注，改跟进中或已结束；发送成功不会自动结案。所有孩子资料都展示为家长自报信息，不猜测事件对应哪个孩子。

模拟失败演示：在后端 `.env` 设置 `MOCK_MAIL_FAILURES=1`，重启worker。新任务第一次失败进入重试，后续模拟成功。或通过后端测试自动验证这一场景。不要切成SMTP进行测试。

## 上传资料

支持PDF、DOCX、XLSX、CSV。先上传草稿，失败查看原因并重试；补全发布单位、业务年度、入学年级、有效期和版本，核对正文再发布。扫描件未启用OCR时明确失败；不要把未解析页面当成完整制度。来源停用不删除历史问答。

## 演示环境恢复

关闭窗口或重启不会清空数据；重新输入手机号也不会恢复旧敏感资料。相同浏览器cookie仍有效时可以修改本次登记资料。演示初始化只执行一次；要全新演示请选择新的数据库文件和原文件目录，不清空既有库。
